# Answers to round 1

1. Interactions not signposted (major): **accepted, partly.** Each line now ends with an instruction that appears only once the components are live, in the visitor's device's words: "Drag a line and the boxes on each side make room." / "Click the clip to copy it." or "Tap the clip to copy it." Without JavaScript the lines stay descriptive, since nothing can be tried. Touch targets are inside the components (not changed here, they keep their own code): Shoji lines already have a 32 px touch strip on coarse pointers; the clip button measures about 33 x 50 px, above the WCAG 2.2 AA minimum of 24 px. The visible artwork is unchanged.
2. Stage sizes (major): **accepted.** Phone stages 256 / 184 / 120 px (Gem needs 184 because the command wraps to four lines at 320 px), gap between entries 44 px, desktop shared stage 296 px (Shoji at 380 x 253 px plus padding; 272 would clip it).
3. Snooze explanation (major): **accepted.** "A button with sleepy eyes." plus, when live: "Bring your pointer close to wake them, then press it: the pupils go round while it pretends to work." (pointer) or "Tap it: the eyes wake up, and the pupils go round while it pretends to work." (touch).
4. Corner marks (minor): **accepted, partly.** Arms 12 -> 8 px; 6 px read as stray dots on a 2x phone screen.
5. Link wording (minor): **refused.** Each link sits directly under its component's name; screen readers already get distinct names ("Open in Experiments: Shoji Bento"). At 15 px with padding the target is about 27 px tall (WCAG 2.5.8 needs 24). Putting the component name in each link triples the visible text for information already on screen.
6. Title (minor): **refused.** "Try three components" is false without JavaScript, where nothing can be tried. The site keeps one large size for the intro and 17 px for everything else; the graph's summary line uses the same 17 px with one serif keyword, and this title mirrors it.
